## Answer

Prioritize evidence of portable runtime behavior and durability over further catalog growth. Current upstream code supplies useful examples of capability conformance, shell differential checking, explicit recovery state, and machine-checked merge records. Six bounded candidates follow. Their external evidence supports the mechanisms; the priorities and implementation proposals are engineering judgments, not claims made by upstreams.

### G1 — Certify provider/harness/profile combinations with executable, version-bound receipts

**P1 · L (5–10 engineering days initially, then incremental) · prerequisite:** #591/#592 fixes merged; no new provider work required.

**Evidence.** LangGraph has an actual capability conformance runner: it creates a fresh saver per capability, invokes behavior suites, and records detected/passed/failed/skipped distinctly. This is code, not a README feature claim. [Runner at `langchain-ai/langgraph@1400d25b7b88cfa055c55b8a82bd95b7c25caef1`](https://github.com/langchain-ai/langgraph/blob/1400d25b7b88cfa055c55b8a82bd95b7c25caef1/libs/checkpoint-conformance/langgraph/checkpoint/conformance/validate.py).

**Local gap.** `docs/runtimes.md` advertises general missions across 14 providers, while `tests/test_openhands_provider.py` uses a scripted `HttpScript` transport and executes the hook separately. Those tests establish our adapter payloads and hook decisions, but do not establish that a particular released agent-server actually consumes the payload and blocks the action. OpenHands' real executor says only exit 2 blocks; other nonzero exits are nonblocking errors. [Executor at `OpenHands/software-agent-sdk@33d8aa29c3078d074799e2fbf5e847aeb2d71360`](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-sdk/openhands/sdk/hooks/executor.py). Existing `capabilities.json` declares capabilities and fallbacks; it has no version-bound live certification receipt.

**Scope/acceptance.** Add a reusable live conformance driver with a frozen case catalog and receipts binding provider version/commit, harness version, OS, profile, test SHA, case IDs, skips, and logs. Start with posix/setsid plus one real external API provider; certify additional combinations incrementally. Exercise task delivery, dependency release, mailbox ack, `ro` write refusal, `rw` out-of-scope refusal, real hook allow/deny handling, retained-worker behavior, commit preservation on stop, and unknown/malformed upstream responses. A missing executable or skipped case produces UNWITNESSED/SKIPPED, never PASS. Generate the public support table from declared-versus-witnessed state. Negative control: disable hook consumption in a fixture server or live disposable setup; the safety case must fail. Do not weaken #562's direct hook tests or imply a mock receipt is live certification.

### G2 — Differentially test the deny-hook's shell lexer against harmless real-shell executions

**P1 · M (3–5 days) · prerequisite:** existing hook regressions retained.

**Evidence.** `mvdan/sh`'s parser tests explicitly confirm parsing against external shells, distinguish shell dialects, and can require external shell tests rather than silently skipping them. [Parser tests at `mvdan/sh@f6d205ab76b3e5e89073130c2229a43be04e1e2a`](https://github.com/mvdan/sh/blob/f6d205ab76b3e5e89073130c2229a43be04e1e2a/syntax/parser_test.go), especially `externalShells`, `REQUIRE_SHELLS`, and `confirmParse`.

**Local gap.** The review history in the current request repeatedly finds mismatches around quoted heredoc delimiters, backslash parity, line continuation, comments, and substitution rewinds. `tests/test_deny_hook.py` contains substantial targeted regressions, but the relevant cases primarily feed strings to the hook rather than comparing generated lexical cases with an execution oracle. The opportunity is a standing test generator, not another one-off regex patch or an assertion that shell parsing can completely constrain arbitrary programs.

**Scope/acceptance.** Define a bounded supported grammar for quotes, continuations, heredocs, comments, substitutions, and pathspec spellings. Generate a deterministic pair corpus: a command containing a harmless sentinel instead of the prohibited effect, plus the corresponding policy string fed only to the hook. Run sentinels in an isolated no-network temp environment with time/output limits; never execute real force pushes or destructive payloads. Compare whether the sentinel executes with whether the hook identifies live versus literal substitution; classify false allowances separately from false denials. Include even/odd backslash parity, adjacent quoted/unquoted word fragments, spaced delimiters, multiple queued heredocs, and multiline substitutions. Preserve minimized failures as frozen regressions; mutate the escaped-opener or delimiter logic and demonstrate a caught counterexample. Pin and report the CI shell dialect/version, and fail the required job if the oracle shell is unavailable. Consider a parser library only after measurement; no mandatory production dependency is justified by this evidence alone.

### G3 — Make worker launch intent durable and reconcile crashes between lifecycle phases

**P1 · M/L (4–7 days) · prerequisite:** #592; can share the G1 crash driver.

**Evidence.** LangGraph's loop explicitly orders pending writes and checkpoints so recovery does not observe a durable checkpoint before its prerequisite writes, and records startup/resume state separately. [Execution loop at `langchain-ai/langgraph@1400d25b7b88cfa055c55b8a82bd95b7c25caef1`](https://github.com/langchain-ai/langgraph/blob/1400d25b7b88cfa055c55b8a82bd95b7c25caef1/libs/langgraph/langgraph/pregel/_loop.py), `_pending_writes` ordering comments near the loop fields. Its conformance tests also exercise write persistence, not just in-process return values. [Write tests at the same commit](https://github.com/langchain-ai/langgraph/blob/1400d25b7b88cfa055c55b8a82bd95b7c25caef1/libs/checkpoint-conformance/langgraph/checkpoint/conformance/spec/test_put_writes.py).

**Local gap, a code-derived hypothesis to reproduce.** `runtime/providers/posix.py:worker_start` first commits `tasks.status='dispatched'`, later inserts dispatch/terminal rows, then starts the monitor, and only at successful return calls `state.save_request(retry_request, ...)`. Python `except BaseException` cleanup handles ordinary exceptions and interrupts; an abrupt process death cannot run it. `local_state.py:get_or_record_request` reads existing requests but does not reserve a new request before those effects. `_sweep_liveness` iterates existing dispatch rows, so it does not cover a claimed task for which no dispatch was inserted. This is a distinct phase-boundary recovery question from #592's Docker termination/sync fix; do not report data loss as reproduced yet.

**Scope/acceptance.** Begin with a subprocess crash matrix at committed claim, worktree creation, dispatch insertion, monitor launch, pid publication, result publication, and sandbox-sync acknowledgement. Persist an intent keyed by request identity and task before effects, with explicit monotone phases and ownership/fencing generation. On restart, reconcile authoritative task/dispatch/backend/worktree state; report ambiguous live effects and retain artifacts rather than guessing. Repeating the same request must identify the same launch or return an explicit recoverable/ambiguous result, never silently duplicate it. Acceptance requires no permanently orphaned claimed task, no duplicate live agent, no fabricated completion, and preservation of a worker commit through retry. Bound the recovery actions and prove stale recovery owners cannot overwrite a newer owner.

### G4 — Convert the single-conductor rule into a recoverable lease and merge receipt

**P2 · M (3–5 days) · prerequisite:** G3's durable transition conventions; promotion remains a human gate.

**Evidence.** gstack now has implemented train verification that fetches authoritative heads, checks a successful gate on the train head, compares the base to the expected prefix tree, emits an expected-head merge condition, and freezes the queue after an interrupted partial train. [Verifier at `garrytan/gstack@c580561e8a5ac08e6cbdd52c7a0ce521ab6310a5`](https://github.com/garrytan/gstack/blob/c580561e8a5ac08e6cbdd52c7a0ce521ab6310a5/lib/ship-queue-train-verify.ts). This does not establish independent mutation verification or justify importing its stamp exemptions.

**Local gap.** `runtime/merge-serialization.md` already requires one conductor per BASE, arrival order, tree-aware review freshness, `--match-head-commit`, egress receipts, and ancestry verification. `diff_scope.py --predict-merge` already offers advisory conflict prediction (#590). In the inspected head no executable conductor/merge-queue owner or BASE-scoped lease exists: `rg --files` finds no `conductor.py`, and the local-state schema has no merge queue or lease table. Thus the candidate is enforcement/recovery of the existing protocol, not a new merge-train algorithm or replacement for expected-head checks.

**Scope/acceptance.** Add BASE-scoped ownership with a fencing generation and a durable queue of accepted `merge_ready` facts. Bind each accepted operation to repo, BASE, expected base/head/tree, reviewed revision, gate artifact digests, and egress receipt. Expose claim/inspect/advance/recover operations; do not auto-merge default or invent human approval. Two concurrent coordinators must not both advance a slot; a stale owner must fail after lease takeover; a moved head/base must force freshness checking; crash after server merge but before ledger update must be reconciled from GitHub plus ancestry without a duplicate merge. Keep upstream merge semantics separate from gstack's version-stamping policy. Omit this package if an uninspected branch already supplies equivalent executable ownership.

### G5 — Correct the A2A compatibility claim and define standards conformance explicitly

**P2 · S/M (1–3 days) · prerequisite:** choose the public contract, not a hosted server.

**Evidence.** A2A's owning proto declares actual AgentCard fields including required supported interfaces (with endpoint URL, binding, protocol version), product version, capabilities, default input/output modes, and skills. [Proto at `a2aproject/A2A@1205f45951ca97c209634ce6046180e38c5dfb30`](https://github.com/a2aproject/A2A/blob/1205f45951ca97c209634ce6046180e38c5dfb30/specification/a2a.proto), messages `AgentInterface`, `AgentCard`, `AgentSkill`.

**Local gap.** `scripts/a2a_export.py` emits project-defined `schema: a2a-agent-card/v1` objects with `id`, mission identity, proof tier, and repository-relative contract strings. `tests/test_a2a_export.py` verifies this project's shape; it does not validate against an official A2A schema. There is no transport endpoint in the exported record. The October-18 research note calls these standard A2A descriptors and implies external discovery: that exceeds what the implementation establishes.

**Scope/acceptance.** Preserve a useful offline mission descriptor under an explicitly project-owned schema/name and correct standard/discovery claims. Document which fields could map to official AgentCard and which remain extensions, with the exact A2A version studied. `--check` must identify its schema accurately. If a real server/endpoint is later supplied, a separate opt-in projection may produce an official card validated with upstream models/schema; reject a missing real endpoint/protocol version rather than inventing one. No HTTP server, remote authentication, or hosted service is required to close the claim-correction issue. Negative controls: the current custom descriptor must fail an official-card check; an incomplete official-card projection must be refused rather than accepted because internal keys exist.

### G6 — Carry source revision and stale-state labels in bounded episodic hints

**P2 · M (2–4 days) · prerequisite:** source inventory convention; no learned-memory database.

**Evidence.** Matt Pocock's current in-progress chief-of-staff recipe explicitly recommends dated, commit-cited durable knowledge and supersession rather than unqualified present-tense claims. This is an instruction recipe, not evidence of a running memory service. [Recipe at `mattpocock/skills@5beb35b040e3de97e54fa9e386d7e42d15c295c2`](https://github.com/mattpocock/skills/blob/5beb35b040e3de97e54fa9e386d7e42d15c295c2/skills/in-progress/chief-of-staff/SKILL.md).

**Local gap.** `search_sessions.py:build_episodic_hint` already caps output, matches touched paths, sanitizes untrusted text, and includes run/unit/status or session ID. It scans `*manifest*.json`, contrary to the older research note's claim that it scans `docs/runs/*.md`. The emitted hint does not include the source path/digest/head revision or a reason to treat a historical invariant as stale relative to the requested base. Reverse lexical filename order is not evidence of recency or relevance. The proposed gap is evidence freshness/inspectability, not absence of recall or trust sanitization.

**Scope/acceptance.** Emit a bounded pointer to each selected source with source digest, recorded code revision/date where available, match reason, and unknown/stale/superseded status. Treat absent provenance as unknown; never silently upgrade a historic run's claim to current truth. Make selection deterministic by declared relevance and recorded recency, retaining the 15-line/token cap and `guard_text` trust envelope. Add fixtures where renamed source paths, superseded claims, missing SHAs, or forged status fields cannot acquire a fresh/current label. Do not automatically mutate historical reports or reuse remembered text as verifier proof. Update the October-18 account to match actual manifest-based retrieval.
