## Findings
- LOW toc.py:107 `at = line.find(marker)` — markers are matched anywhere on a non-fenced line, including inside inline code spans. Probe: `# T\nWrap with \`<!-- toc -->\` and \`<!-- /toc -->\` markers.\n## A\n` with no real pair is treated as a pair, and `--stdout` prints `Wrap with \`<!-- toc -->\n- [A](#a)\n<!-- /toc -->\` markers.`, so a normal write would corrupt that prose. If a real pair also exists, the input fails safe with exit 2 (probe prose2.md). Not a regression: the round-1 regex had the same behavior and was worse. A doc that mentions both markers in inline code and has no real pair is the only silent case. Unguarded; acceptable to defer. Suggested fix: skip code spans when searching, or require each marker alone on its line.
