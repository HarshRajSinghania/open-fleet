## Findings

### Required

**R1. Duplicate suffix can collide with an existing slug (AC-2)** — `mdtoc/toc.py:53`
> `slugs.append(base if n == 0 else f"{base}-{n}")`

The generated `base-n` is never checked against slugs already issued. Probe: `slugify_all(["A","A","A-1","A"])` returns `['a','a-1','a-1','a-2']`, so two headings share the anchor `#a-1`. GitHub's slugger keeps incrementing until the slug is unused and yields `a, a-1, a-1-1, a-2`. Unguarded: `test_duplicates_get_suffixes_in_order` has no heading whose own slug looks like a suffix.

**R2. Slug is computed from raw markdown, not rendered text (AC-2)** — `mdtoc/toc.py:43`, `:63`
> `return _DROP.sub("", text.lower()).replace(" ", "-")`

GitHub slugs the rendered heading text. Probe: `render_toc("## **Bold** [l](u)\n")` returns `- [**Bold** [l](u)](#bold-lu)\n`. GitHub's anchor is `#bold-l`. Links, emphasis and code spans give wrong anchors, and the nested `[l](u)` inside the link label (`:63`, `- [{h.text}](#{slug})`) breaks the link text. Unguarded: no test uses inline markup.

**R3. Fence opened on a list-item line is not detected (AC-3)** — `mdtoc/toc.py:7`
> `_FENCE = re.compile(r"^ {0,3}(`{3,}|~{3,})(.*)$")`

The fence must start the line after ≤3 spaces, so `- ```` is never a fence open. Probe: `scan_headings("- ```\n  # x\n  ```\n")` returns `[Heading(level=1, text='x')]`. A heading inside code is emitted, which AC-3 forbids. A fence on its own indented line in a list (`  ```` after `- item`) is handled correctly, and fences nested 4+ spaces deep never match `_HEADING` either, so only the item-line opener leaks. Unguarded: no test places a fence in a list.

### Optional

**O1. Combining marks and tabs dropped from slugs** — `mdtoc/toc.py:9`
> `_DROP = re.compile(r"[^\w\- ]")`

`\w` excludes Mn, so `"café́"` slugs to `café`. GitHub keeps `\p{M}`. A tab inside a heading is removed instead of being treated like the other dropped whitespace/punctuation. Low impact (NFD input).

### Nit

**N1. Empty headings render as empty links** — `mdtoc/toc.py:38`
> `headings.append(Heading(len(h.group(1)), (h.group(2) or "").strip()))`

Probe: `render_toc("## \n## b\n")` returns `- [](#)\n- [b](#b)\n`. An empty heading still consumes a duplicate slot (correct for numbering) but should not be rendered as a link.

**N2. `or` conflates 0 with unset** — `mdtoc/cli.py:46`
> `sys.stdout.write(render_toc(text, max_level=args.max_depth or DEFAULT_MAX_LEVEL))`

`--max-depth 0` silently becomes depth 4. Range checking is AC-5 (later slice), so this is only a note for that slice. With several files, TOCs are concatenated with no separator.

### FYI

**F1. `--stdout` wiring preserves F0 behavior.** Without `--stdout`, a file is still only read (`mdtoc/cli.py:40`, `text = Path(name).read_text(encoding="utf-8")`) and exits 0. The error path still prints to stderr, sets `status = 2`, and now `continue`s (`mdtoc/cli.py:44`), so a bad file never reaches `render_toc`. All five F0 tests in `tests/test_smoke.py` are untouched and pass, including `test_existing_utf8_file_exits_zero` and `test_missing_file_exits_two`.

**F2. Standards.** `toc.py` is small, stdlib-only and typed with `NamedTuple`, matching the F0 style. `DEFAULT_MIN_LEVEL` is exported but `cli.py` only imports the max, which is fine for now. The fence close rule (`m.group(1)[0] == fence[0]`, `len(m.group(1)) >= len(fence)`, `not m.group(2).strip()`) correctly follows CommonMark.
